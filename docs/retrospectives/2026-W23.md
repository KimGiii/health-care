## 잘 된 것 (Good)

- **인증을 화면 하나가 아닌 가입 계약으로 완성**: Apple·Google 버튼만 붙이지 않고 nonce, JWKS, 동시 가입, 약관 동의까지 연결해 보안과 제품 요구를 함께 처리했다.
- **현지화를 인프라부터 전 화면까지 한 번에 관통**: 문자열만 번역하지 않고 locale, 날짜 선택기, 서버 fallback까지 묶어 언어 전환 시 끊기는 지점을 줄였다.
- **관측 지표가 실제 개선으로 이어짐**: 전 주에 만든 p99 지표로 N+1과 누락 인덱스를 찾아 배치 조회로 고쳤다. 모니터링이 대시보드 장식이 아니라 수정 근거가 됐다.
- **dev/prod 경계를 코드와 시크릿 양쪽에서 분리**: 실기기 검증이 prod 설정에 기대지 않도록 Terraform, CI environment, xcconfig를 함께 정리했다.

## 아쉬운 것 (Bad)

- **IAM 권한 수정이 잘게 반복됨**: 필요한 EC2·ECR·Route53·S3·IAM 권한을 한 번에 모델링하지 못해 여러 보완 커밋이 생겼다.
- **blue-green sed 수정이 세 차례 이어짐**: Grafana 포트 오염, 파이프 문자 이스케이프, 8080·8081 치환 범위 문제가 순차적으로 드러났다. 문자열 치환에 배포 핵심 로직이 과하게 의존했다.
- **환경 변수 우선순위가 불명확했음**: scheme의 `BASE_URL`이 xcconfig를 덮어써 실기기에서 잘못된 서버를 바라봤다. 환경별 단일 진실 공급원을 초기에 고정하지 못했다.
- **대규모 영문화의 회귀 범위가 큼**: 짧은 기간에 화면 대부분을 수정해 레이아웃 잘림, 누락 키, 언어별 날짜 표현을 체계적으로 검증할 자동화가 더 필요해졌다.

## 배운 것 (Learned)

- **iOS 빌드 설정은 우선순위 자체가 설계다**: scheme environment, xcconfig, Info.plist가 같은 값을 가질 때 어느 계층이 기준인지 명시하지 않으면 실기기에서만 환경 오염이 발생한다.
- **소셜 로그인은 identity token 검증만으로 끝나지 않는다**: nonce 재사용 방지, provider subject의 유일성, 동시 가입, 필수 약관 동의를 하나의 가입 상태 머신으로 다뤄야 한다.
- **blue-green 전환은 구조화된 설정 변경이 안전하다**: 범용 sed로 숫자를 바꾸면 무관한 포트까지 손상시킬 수 있다. 명시적인 upstream 파일이나 포트별 치환처럼 변경 범위를 제한해야 한다.
- **국제화는 서버 오류까지 포함한다**: 앱 문자열을 모두 번역해도 서버 메시지가 한국어로 고정되면 사용자 경험이 깨진다. 안정적인 오류 코드와 클라이언트 fallback이 필요하다.
