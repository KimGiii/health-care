# 0004. 완성요리(복합 식품)를 추천 후보로 도입한다

## Status

Proposed

## Context

현재 추천 큐레이션과 엔진은 **단일 식재료 조립** 모델이다.

- 추천 가능(RECOMMENDABLE) 풀은 V25 시드 allowlist **42개 단일 식재료**(현미밥·닭가슴살·브로콜리·사과…)뿐이다. MFDS 임포트 식품은 전부 `SEARCH_ONLY`이고, 이를 추천 후보로 승격하는 코드는 없다.
- 엔진(`ConstraintRecommendationEngine`)은 끼니마다 `PREFERRED_CATEGORIES`(GRAIN·PROTEIN_SOURCE·VEGETABLE…)에서 식재료를 한 개씩 골라 조립한다. 사용자가 받는 결과는 "현미밥 + 닭가슴살 + 브로콜리"식 조합이지, **"제육덮밥 한 그릇" 같은 완성요리가 아니다.**

그러나 카탈로그에는 완성요리 데이터가 이미 충분하다.

- `MFDS_STANDARD_DISH`(음식 표준데이터)는 닭고기덮밥·닭볶음(닭갈비)·섞어찌개·불고기샐러드 등 **표준 한식 완성요리 수천 개**를 끼당 영양정보와 함께 담고 있다.
- `MFDS_STANDARD_PROCESSED`에도 김밥·카레·불고기라이스·김치찌개 등 완제품 형태의 요리가 다수 있다.
- 문제는 데이터가 아니라, 이들이 전부 `PROCESSED`/`SEARCH_ONLY`로 묻혀 있고(역할·품질 미분류), 엔진이 이를 한 끼로 다루는 모델이 없다는 것이다.

완성요리를 **안전하게** 추천하려면 알러젠을 알아야 한다. 제육덮밥 = 돼지고기 + **고추장(대두·밀)** + 밥이므로, 요리 이름·구성에서 알러젠을 분석하지 않으면 strict 알러지 모드에서 위험하다. 현재 알러젠 태그(`food_allergen_tags`)와 신뢰도(`AllergenConfidenceLevel`)는 단일 식품 직접검증 위주이고, 복합요리는 미태깅이다. 이 결정은 `feat/allergen-recommendation` 브랜치의 핵심 목표와 직결된다.

전제 변경(이미 반영): 추천 제공량은 검증된 1회 제공량 옵션에서만 선택한다(§7.1, `ServingOptionDeriver`). 완성요리도 1인분 제공량 옵션이 있어야 추천 대상이 된다.

## Decision

### 1. 음식 역할(food role) 분류 도입

`FoodCatalog`에 추천 의미의 역할 속성을 둔다.

- `MAIN_DISH` — 한 끼를 구성하는 완성요리 (덮밥·비빔밥·찌개·볶음·구이·국/탕·면류 등)
- `INGREDIENT` — 단일 식재료 (현미밥·닭가슴살·브로콜리)
- `SIDE` — 반찬·곁들임 (나물·김치·샐러드)
- `EXCLUDED` — 소스·분말·시럽·드레싱·주류·첨가물 등 추천 부적합

도출은 **결정적 규칙**으로 한다(재현 가능, 외부 의존 없음):

- 이름 패턴: `덮밥|비빔밥|볶음밥|국밥|찌개|전골|볶음|구이|조림|찜|국|탕|면|파스타|카레|덮밥|샐러드…` → MAIN_DISH 후보, `소스|분말|시럽|드레싱|양념|믹스|농축…` → EXCLUDED.
- 매크로 프로필: 단백질과 탄수화물이 동시에 유의미하면 완성요리 신호(한 끼 균형).
- source 가중: `MFDS_STANDARD_DISH` 우선, 브랜드 SKU성 이름은 감점.

분류는 import 시 또는 별도 분류 배치로 수행하며, 추천 동작은 바꾸지 않는다(분류만).

### 2. 규칙 기반 자동 큐레이션

수작업 42개 allowlist를 대체·보강한다. `MAIN_DISH`(+선별된 `INGREDIENT`/`SIDE`) 중 품질 게이트를 통과한 후보를 `RECOMMENDABLE`로 승격한다.

품질 게이트: 매크로 완전성, 현실적 1인분 제공량 존재, canonical 그룹 대표, 알러젠 태깅 완료, source 신선도(`DataFreshnessPolicy`). 운영자 검수는 기존 `verification-priority`로 보조하되, **승격 자체는 규칙으로 자동화**해 풀을 시드 너머로 확장한다.

### 3. 복합요리 알러젠 분석

요리 이름·구성에서 재료를 유추해 알러젠을 태깅한다(키워드→알러젠 매핑: 고추장→대두·밀, 우유/치즈→유, 새우→갑각류, 계란→난류 …).

직접검증보다 신뢰도가 낮으므로 `AllergenConfidenceLevel`에 **추론(INFERRED) 등급**을 추가하고, strict 알러지 모드의 취급 정책을 명시한다. 안전 최우선 원칙상 strict 모드에서는 추론 알러젠 보유 요리를 **보수적으로 제외**하거나 명시 경고를 동반한다(ADR-0001과 정합). 면책 고지를 유지한다.

### 4. 엔진의 dish-중심 끼니 모드

끼니 구성을 두 모드로 일반화한다.

- **dish-first**: 끼니 = 완성요리 1개 (+ 선택적 채소 곁들임). `MAIN_DISH`는 단독으로 끼니 칼로리·매크로 목표를 채우는 후보가 된다. `PREFERRED_CATEGORIES` 단일재료 조립에 의존하지 않는 변형을 추가한다.
- **ingredient-assembly**: 기존 단일재료 조립(샐러드·직접 구성 선호 대비) 유지.

제공량 결정은 기존 1회 제공량 옵션 조합 탐색(`chooseServingCombination`)을 그대로 재사용한다. 두 모드의 해는 동일한 budget hard constraint·실패 계약(ADR-0003)을 따른다.

### 5. 중복 제거(canonical 그룹)

`canonical_group_id`로 "닭볶음(닭갈비)" 수십 변형을 대표 1개로 묶어 추천한다(이미 V35·`isCanonicalCandidate()` 존재). 그룹 단위 노출·통계로 다양성을 확보한다.

## Consequences

- 추천이 "제육덮밥·닭고기덮밥·김치찌개" 같은 **완성요리**로, 현실적 1인분 분량에 맞춰 나온다. 사용자 기대에 부합한다.
- 단일재료 조립 모드는 유지되어 두 모델이 공존한다(엔진 복잡도 증가 — benchmark에 dish 시나리오 추가 필요).
- 데이터 정제 작업이 따른다: `MFDS_STANDARD_DISH`의 `PROCESSED` 오분류 재매핑, 저품질(예: 섞어찌개 39kcal/100g)·중복·SKU성 항목 필터.
- 복합 알러젠은 **추론**이라 오탐/누락 위험이 있다. 신뢰도 등급·strict 정책·면책 고지로 안전을 관리하되, 직접검증 데이터 확보 시 우선 대체한다.
- 마이그레이션: `food_role` 컬럼, 알러젠 추론 태그(confidence) 확장, 큐레이션 재실행. 기존 시드 allowlist는 규칙 큐레이션으로 흡수한다.

## 단계 계획 (exec-plan 반영)

- **Phase A** — `food_role` 분류기 + 마이그레이션 + 단위 테스트. 추천 동작 불변, 분류만.
- **Phase B** — 복합요리 알러젠 추론 태깅 + `INFERRED` 신뢰도 + strict 모드 정책.
- **Phase C** — 규칙 기반 dish 큐레이션(자동 승격) + 1인분 제공량 옵션(`ServingOptionDeriver` 재사용).
- **Phase D** — 엔진 dish-중심 끼니 모드 + benchmark dish 시나리오.
- **Phase E** — canonical 중복 제거 적용·그룹 단위 추천.

## Open Questions

- `food_role` 도출을 import 파이프라인에 둘지, 독립 분류 배치로 둘지.
- 복합 알러젠 추론 신뢰도가 낮을 때 strict 모드 기본 동작: 제외 vs 경고.
- 끼니당 완성요리 1개 + 곁들임 허용 범위(0~1개?).
- dish 모드와 ingredient 모드를 사용자가 선택하는지, 자동 혼합하는지.
- 이름→재료→알러젠 매핑 사전의 출처·검증·유지보수 주체.
