# 0002. 검증된 후보로 목표별 남은 영양량을 제약 최적화한다

## Status

Accepted

## Context

식품 카탈로그는 공공데이터 3개 source를 합치면 약 50만 건까지 커질 수 있다. 그러나 데이터 건수가 많다는 사실은 알러젠 정보, 영양값, 제공량, 중복 식품, 실제 추천 가능성을 보장하지 않는다.

현행 추천은 모든 목표에 같은 칼로리·단백질 허용 범위를 적용하고, 날짜 회전과 카테고리 우선순위로 식품을 고른 뒤 제공량을 25g 단위로 조절한다. 이미 섭취한 식단, 목표 기간, 목표별 비대칭 제약, 영양 데이터 불확실성, 사용자별 피드백은 목적함수에 포함하지 않는다.

ADR-0001의 기본 베스트에포트 모드는 알러젠 태그가 없으면 미검토 식품도 통과시킨다. 이는 "등록한 알러지 조건은 절대 위반하지 않는다"는 새 제품 원칙과 맞지 않는다.

## Decision

### 1. 안전 계약

- `food_allergen_tags`의 포함 태그 의미는 유지한다.
- 알러지를 등록한 사용자의 추천은 매칭 포함 태그가 없어야 하며, 완결 알러젠 프로필이 `DIRECT_VERIFIED` 또는 `LABEL_DERIVED` 근거로 검증된 식품만 통과시킨다.
- 알러젠 프로필 검증은 포함 태그가 0개인 식품도 표현할 수 있어야 하므로 태그 행의 boolean이 아니라 별도 프로필/검토 근거 모델로 확장한다.
- `RECIPE_DERIVED`, 일반 음식명, AI 추론은 검수 큐를 만드는 데 사용할 수 있지만 안전 게이트를 통과시키는 최종 근거로 사용하지 않는다.
- 기존 `strictAllergyMode` 요청 필드는 호환 기간을 둔 뒤 폐기한다. 호환 기간에도 알러지 제한이 있으면 서버의 verified-only 게이트가 우선한다.

### 2. 목표별 영양 정책

- 식단 추천은 하나의 대칭 오차 함수가 아니라 목표별 hard constraint와 soft objective를 사용한다.
- 체중 감량과 체형 개선은 계산된 목표 열량 미만을 상한으로 사용한다.
- 근육량 증가는 단백질 목표 이상을 하한으로 사용한다.
- 지구력 향상은 탄수화물과 열량 부족을 별도 정책으로 다룬다.
- 건강 유지는 목표 범위 안의 균형을 사용한다.
- 정확한 비율과 안전 경계는 코드 상수가 아니라 버전이 있는 정책으로 관리하고 benchmark와 제품 검토를 거쳐 변경한다.

### 3. 목표 기간과 진행 보정

- 사용자가 입력한 목표일은 희망 일정이며 안전 경계를 무시하는 deadline이 아니다.
- 목표 변화량과 남은 기간으로 초기 영양 목표를 계산하되, 권장 범위를 벗어나면 달성 가능한 예상 날짜를 제안한다.
- 실제 진행은 일일 변동이 아니라 주간 추세로 평가하고 목표 열량과 예상 달성일을 주 1회 재계산한다.
- 운동 소모 열량은 TDEE와 중복될 수 있으므로 식사 예산에 1:1로 더하지 않는다.

### 4. 남은 하루 공동 최적화

- 추천 전에 기록된 식단의 영양을 일일 목표에서 차감한다.
- 남은 끼니는 각각 독립적으로 고르지 않고 하나의 최적화 문제로 계산한다.
- 하루 총 영양 목표는 hard constraint, 끼니별 분배와 다양성은 soft constraint다.
- 미검증 또는 AI 추정 섭취 기록은 열량에는 보수적인 상한, 단백질에는 보수적인 하한을 사용한다.

### 5. 후보와 제공량

- 검색·기록 가능 카탈로그와 추천 가능 풀을 분리한다.
- 추천 자격은 추천 큐레이션 상태 하나로 결정하지 않고 알러젠 프로필, 목표별 필수 영양 완전성, 제공량 근거, 데이터 버전 상태를 함께 평가한다.
- 추천 엔진은 임의 g 대신 검증된 이산 제공량 옵션을 사용한다.
- 사용자의 실제 식단 기록은 제공량 프리셋을 우선하되 직접 g 입력을 허용한다.
- 여러 source의 동일 식품은 비파괴 canonical 그룹으로 묶고 추천·피드백·통계를 그룹 기준으로 계산한다.

### 6. 엔진과 학습 루프

- DB hard filter와 후보 축소 후 제한 시간 내 제약 최적화로 상위 복수 해를 생성한다.
- 영양·안전 hard constraint를 통과한 해 안에서 최근 반복, 사용자 선호, 다양성을 순위화한다.
- 충족 가능한 해가 없으면 제약을 조용히 완화하지 않고 구조화된 실패 원인을 반환한다.
- 추천 스냅샷과 노출, 재추천, 기록 전환, 삭제·교체, 선택형 재추천 사유를 저장한다.
- 사용자 연결 이벤트는 기본 90일만 유지하고 장기 분석은 비식별 집계로 수행한다.

### 7. 배포 게이트

- 목표 유형, 알러지 조합, 이미 섭취한 영양, 남은 끼니 수를 조합한 고정 benchmark를 운영한다.
- 알러지·기피 또는 목표별 hard constraint 위반은 1건이라도 배포를 차단한다.
- 검증 식품 수 자체가 아니라 조건별 추천 성공률, 영양 오차, 현실적 제공량, 반복률, 기록 전환율을 품질 지표로 사용한다.

## Consequences

- 추천 가능 풀은 전체 카탈로그보다 훨씬 작아진다. 검증 풀을 넓히는 운영 파이프라인이 핵심 제품 역량이 된다.
- 기존 기본/Strict 2모드 중 알러지 사용자의 완화된 기본 모드는 폐기된다. ADR-0001의 포함 태그 의미와 의료적 한계는 유지되지만 모드 기본값 결정은 본 ADR이 대체한다.
- 목표·영양 정책, 제공량, canonical 그룹, 알러젠 프로필, 추천 이벤트를 위한 스키마와 API 변경이 필요하다.
- 기존 greedy 엔진은 즉시 삭제하지 않고 benchmark를 기준으로 단계적으로 교체한다.
- 추천 결과가 조금 느려질 수 있으므로 후보 축소, 제한 시간, 재현 가능한 상위 해 선택이 필요하다.
- 이 결정은 의료적 안전 보증이 아니다. 교차오염과 실제 제품 변경은 사용자 안내와 데이터 만료 정책으로 다룬다.
