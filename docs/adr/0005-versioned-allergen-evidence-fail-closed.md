# 0005. 알러지 추천은 버전된 근거와 fail-closed 완결 프로필로 판정한다

## Status

Accepted — 2026-06-22

## Context

ADR-0001은 포함 태그와 Strict 모드를 함께 도입했지만, 사용자가 안전 수준을 토글하는 2모드 계약과 태그 행의 `allergen_profile_verified` 플래그는 "태그가 없음"과 "해당 알러젠을 검토해 없음이 확인됨"을 안정적으로 구분하지 못한다. 또한 현재 모델은 실제 원재료 포함과 교차접촉 가능성, 여러 출처의 근거 충돌, 검토한 알러젠 표준 범위를 표현하지 못한다.

알러지 추천은 누락 데이터를 통과로 해석하지 않아야 하지만 의료적 안전을 보증하지도 않는다. 기피 식품과 향후 글루텐 프리 같은 식이 기준은 알러지와 다른 판정 근거를 가지므로 같은 태그 선택 흐름에 섞지 않는다.

## Decision

### 제한 계약

- 알러지 등록은 `ALLERGY + ALLERGEN_TAG`만 허용한다. 알러지와 기피 설정 화면을 분리하고 신규 `AVOID + ALLERGEN_TAG`는 UI·API·DB에서 막는다. 나머지 기피 정책은 이번 결정의 범위 밖이며 현행을 유지한다.
- 알러지가 하나라도 등록된 추천은 항상 verified-only다. `strictAllergyMode` 사용자 토글은 제거하고, API 호환 기간에는 필드를 받되 판정에는 사용하지 않는다.
- 알러지가 없는 사용자는 알러젠 프로필이 없다는 이유만으로 추천 후보에서 제외하지 않는다.
- 지원 목록 밖의 자유 입력 알러지와 심각도 입력은 받지 않는다. 알러젠 태그는 정책 버전과 고정 benchmark를 통과한 항목만 활성화한다.

### 근거와 프로필

- 출처별 알러젠 근거를 비파괴로 보존한다. 근거는 최소한 알러젠 태그, 관계(`CONTAINS` 또는 `MAY_CONTAIN`), 신뢰 수준, 출처, 원문 참조, 근거 버전, 검토일, 유효 상태를 가진다.
- 제한 태그와 일치하는 유효 `CONTAINS` 또는 `MAY_CONTAIN` 근거가 하나라도 있으면 추천에서 제외한다.
- `RECIPE_DERIVED`는 포함 알러젠을 발견해 차단하는 양성 근거로만 사용한다. 표준 레시피에 특정 알러젠이 없다는 사실은 통과 근거가 아니다.
- 통과 근거는 `DIRECT_VERIFIED` 또는 `LABEL_DERIVED` 완결 알러젠 프로필이다. 프로필은 검토한 태그 집합, 표준 버전, 출처, 근거 참조, 검토일, 유효기간, 무효화 이력을 가진다.
- 포함·교차접촉 태그가 0개여도 전체 범위를 검토한 유효 프로필은 표현할 수 있다. 사용자의 모든 제한 태그가 프로필의 검토 범위에 포함돼야 통과한다.
- 동일 제품의 더 최신 공식 전체 라벨은 조건을 충족하면 이전 근거를 판정에서 대체하되 이력은 보존한다. 서로 다른 유효 근거가 충돌하면 자동 우선순위를 적용하지 않고 fail-closed로 차단한다.
- 제품 사실이나 데이터 버전이 바뀌었는데 새 완결 알러젠 자료가 없으면 기존 프로필을 무효화한다. 브랜드·라벨 프로필은 출처별 만료 정책을 적용한다.

### 운영과 전환

- 알러젠 근거·프로필은 하나의 적재 트랜잭션에서 함께 생성·교체·무효화한다.
- 영양·제공량, 데이터 만료, 알러젠 만료·무효화·충돌은 하나의 관리자 작업함 아래 유형별 재검증 하위 큐로 제공한다.
- 추천 스냅샷은 `allergyPolicyVersion`, 제한 태그 집합, 식품별 프로필·근거 버전을 저장한다. 사용자 연결 원본은 90일 후 제거하고 장기 지표는 비식별 집계만 유지한다.
- 일반 식단 기록 API는 사용자의 기록 자유를 위해 유지한다. 추천 끼니를 기록하는 전용 전환 API는 현재 제한과 근거를 다시 검증하고 `snapshotId + mealType` 단위로 멱등 처리한다.
- 추천 결과는 검증 출처와 검토일을 보여주되 "안전한 식품"이라고 표현하지 않는다. 실제 제품과 제조 환경이 다를 수 있으므로 섭취 전 라벨 확인을 안내한다.

글루텐 프리처럼 검증된 속성을 요구하는 기능은 별도 `DIETARY_REQUIREMENT` 계약으로 다루며 이번 구현 범위에는 포함하지 않는다.

## Consequences

- 알러지 사용자의 추천 후보가 줄고, 데이터가 부족하거나 정책이 비활성화된 태그는 성공 추천 대신 구조화된 실패를 반환한다.
- 기존 `food_allergen_tags` 단일 출처 행과 legacy 프로필 플래그를 출처별 근거 모델로 이전해야 한다.
- 알러젠별 단일·복합 제한 benchmark, 충돌·만료 운영 흐름, 추천 전환 재검증이 출시 조건이 된다.
- ADR-0001의 기본/Strict 2모드와 태그 행 기반 완결성 결정을 이 ADR이 대체한다. ADR-0002의 verified-only 방향과 목표별 영양 hard constraint는 유지한다.
