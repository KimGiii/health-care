# 0001. 식단 기록 규칙을 유스케이스 모듈에 둔다

## Status

Accepted

## Context

식단 기록 HTTP 컨트롤러는 생성, 목록, 단건 조회, 수정, 삭제 엔드포인트를 제공하지만 실제 규칙은 식단 기록 저장 흐름에 있다. 사용자 소유권 검증, 식품 카탈로그 검증, 식품 항목별 영양 계산, 식단 기록 영양 합계, 식품 카탈로그 사용 횟수 증감이 함께 움직인다.

기존 `DietLogService` 이름은 이 모듈을 일반 서비스처럼 보이게 만들었고, 컨트롤러와 식단 사진 분석 확정 흐름이 동일한 식단 기록 규칙을 사용한다는 점이 덜 드러났다.

## Decision

식단 기록 규칙의 테스트 표면을 `DietLogUseCases`로 명명하고 `com.healthcare.domain.diet.usecase` 패키지에 둔다.

HTTP 컨트롤러는 요청/응답 매핑과 상태 코드만 담당하고, 식단 사진 분석 확정 흐름도 같은 `DietLogUseCases`를 호출한다.

## Consequences

- 식단 기록 생성, 조회, 수정, 삭제의 규칙은 `DietLogUseCasesTest`에서 검증한다.
- 컨트롤러 테스트는 인증/인가 및 HTTP edge 동작에 집중한다.
- 식단 사진 분석에서 식단 기록을 만드는 흐름은 별도 저장 규칙을 재구현하지 않고 같은 유스케이스를 재사용한다.
- 이후 식단 기록 입력 흐름이 더 복잡해지면 먼저 `DietLogUseCases` 안에서 깊이를 유지하고, 별도 모듈 추출은 중복 adapter나 명확한 독립 규칙이 생길 때 검토한다.
